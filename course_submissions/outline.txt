Project Title: Secure RAG Gateway: Defending an LLM Application Against Prompt Injection, Knowledge-Base Poisoning, and Excessive Agency

1. Overview and Objectives

Build a Retrieval-Augmented Generation (RAG) chatbot and a layered security architecture around it.
Identify the threats specific to RAG and agentic AI systems, implement controls against each, and verify the controls with attack testing.

2. System Under Protection

Baseline application: document store, embeddings, retrieval, local LLM (Ollama, Llama 3.1).
Assets to protect: the knowledge base, user data, the system prompt, and the agent's tool actions.
Architecture: user → security gateway → RAG pipeline → LLM → agent tools → output check, with audit logging at every step.

3. Threat Model

Attacker capabilities: can submit queries and can add documents to the corpus.
Attack scenarios:
Direct prompt injection
Indirect injection through a poisoned document
Knowledge-base poisoning
Sensitive data leakage in model output
Unauthorized tool calls (excessive agency)
Threats are mapped to the OWASP Top 10 for LLM Applications.
Out of scope: attacks on the model itself and infrastructure compromise.

4. Security Controls

Threat	Control	Component
Direct prompt injection	Pattern and classifier-based input screening	Security gateway
Sensitive data exposure	PII redaction on input, leak filtering on output	Security gateway
Abuse and cost attacks	Per-user rate limiting	Security gateway
Knowledge-base poisoning	Embedding outlier detection, instruction scanning, source trust scoring	Poisoning detector
Excessive agency	Tool allow-list, request-consistency check on sensitive tools	Agent guardrails
Lack of visibility	Audit logging of every decision	All components

5. Implementation

Stack: Ollama, LangChain, PostgreSQL with pgvector, FastAPI, Redis.
Build order: manual RAG baseline, LangChain version, gateway, guardrails, poisoning detector, agent layer.
Deployment: Docker Compose, then local Kubernetes (kind) with NetworkPolicies for isolation. Everything runs locally at no cost.

6. Security Testing and Evaluation

An attack suite and a benign suite, each run with controls off and then on.
Metrics: detection rate, false-positive rate, and latency overhead.
Demonstrations: each attack succeeds without controls and is blocked with them.

7. Results and Residual Risk

What the controls caught, what got through and why, and known limitations.

8. Conclusion and Future Work
